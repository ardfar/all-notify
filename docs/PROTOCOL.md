# Wire Protocol & E2EE Specification

Protocol version: **`1`**

All three codebases (`server/`, `android/`, `desktop/`) MUST conform to this specification and pass the shared test vectors in `protocol/test_vectors.json`.

---

## 1. End-to-End Encryption (E2EE)

### Primitives
- **Master Group Key (`K_master`)**: 32-byte (256-bit) cryptographically random key generated once during initial setup. Never sent to the VPS.
- **Key Derivation**: `HKDF-SHA256` with empty salt and domain-separated `info` strings:
  - Event payload key: `K_event = HKDF-SHA256(K_master, salt="", info="all-notify:v1:event", len=32)`
  - Blob payload key: `K_blob  = HKDF-SHA256(K_master, salt="", info="all-notify:v1:blob",  len=32)`
- **AEAD Cipher**: **`XChaCha20-Poly1305`** (24-byte random nonce per encryption, 16-byte authentication tag).
  - Go: `golang.org/x/crypto/chacha20poly1305` (`NewX`)
  - Rust (Tauri): `chacha20poly1305` crate (`XChaCha20Poly1305`)
  - Kotlin (Android): `Lazysodium` / `Tink` or `BouncyCastle` / pure Kotlin `XChaCha20Poly1305` (validated against `protocol/test_vectors.json`)

### Ciphertext Binary Format
```text
[ 24-byte random nonce ] || [ ciphertext || 16-byte Poly1305 tag ]
```
When embedded in JSON (WebSocket envelopes), this byte array is encoded as **URL-safe base64 without padding** (`base64url`). When uploaded as an HTTPS blob, it is sent as raw `application/octet-stream`.

### Associated Authenticated Data (AAD)
To prevent envelope tampering or replay across event types/senders:
- **Events**: `AAD = "v1|" + event_id + "|" + sender_device_id` (UTF-8 bytes)
- **Blobs**: `AAD = "v1|blob|" + blob_id` (UTF-8 bytes)

### Key Rotation
If a device is lost or compromised:
1. Revoke the lost device's auth token on the VPS (`all-notify-server token revoke <device_id>`).
2. Generate a new `K_master` and re-pair remaining devices (or update their group key).

## 2. Device Pairing URI & QR Code

Devices are paired by scanning a QR code or pasting a setup URI:

```text
allnotify://pair?v=1&url=https%3A%2F%2Fnotify.example.com&token=<device_token>&key=<base64url_K_master>&device_id=<device_id>&name=<url_encoded_device_name>
```

| Parameter | Description |
| :--- | :--- |
| `v` | Protocol version (`1`). |
| `url` | Base HTTPS URL of the VPS relay (no userinfo, query, or fragment; trailing `/` stripped; client derives `ws_url` as `wss://<host>[<path>]/v1/ws`). |
| `token` | Per-device bearer token minted by the VPS server. |
| `key` | 32-byte `K_master` encoded in `base64url` (no padding). |
| `device_id` | Server-assigned stable ID for this device (e.g. `dev_01J...`). |
| `name` | Human-readable label (e.g. `Pixel 9`, `MacBook Pro`). |

> **Security**: `K_master` is never stored on or sent to the VPS. QR codes are rendered in the browser (web admin) or on a trusted device, never on the server.

### Pairing Link v2 (One-Time Code) — Phase 5

```text
allnotify://pair?v=2&url=<urlenc_https_url>&code=<pc_xxxxxxxxxxxxxxxxxxxxxx>&key=<base64url_K_master>&name=<urlenc_name>
```

v2 replaces `token` + `device_id` with a single-use, 10-minute `code` redeemed via `POST /v1/pair/claim`. Clients MUST accept both `v=1` and `v=2`. Full rules, Key Check Value (KCV, `info="all-notify:v1:kcv"`), claim API, and test-vector additions: see [PAIRING.md](./PAIRING.md).

## 3. WebSocket Protocol

### Connection & Authentication
- Endpoint: `GET /v1/ws` (upgraded to WebSocket)
- Headers:
  - `Authorization: Bearer <device_token>`
  - `X-AllNotify-Protocol: 1`
- Optional query param: `?after_seq=<last_acked_seq>` (integer, defaults to server's stored cursor for this device).
- Keepalive: Server sends WebSocket `Ping` every **30 seconds**; client responds with `Pong`. Connection is dropped if no pong/activity for **90 seconds**.
- Client reconnect: Exponential backoff `1s -> 2s -> 4s -> 8s -> 15s -> 30s` (with ±20% jitter), immediately reset on network connectivity change.

### Outer Frames (Plaintext Routing Layer — Visible to VPS)

Every WebSocket text frame is a JSON object with a `op` field.

#### 1. Client → Server: Publish Encrypted Event (`relay`)
```json
{
  "op": "relay",
  "event_id": "01JABCDEF1234567890ABCDEFG",
  "target": "broadcast",
  "ciphertext": "<base64url(nonce || ct || tag)>"
}
```
- `event_id`: ULID or UUIDv7 generated by the sender (unique, roughly time-ordered).
- `target`: `"broadcast"` (all other registered devices).
- Max frame size: **64 KB** (images go through the HTTPS Blob API, not WS).

#### 2. Server → Client: Deliver Encrypted Event (`event`)
```json
{
  "op": "event",
  "seq": 4821,
  "event_id": "01JABCDEF1234567890ABCDEFG",
  "sender_device_id": "dev_01J...",
  "server_ts": 1764060000123,
  "ciphertext": "<base64url(nonce || ct || tag)>"
}
```
- `seq`: Monotonically increasing integer per-server sequence number used for ACKs and offline replay.

#### 3. Server → Client: Offline Replay Boundary (`replay_complete`)
Sent immediately after connecting once all queued offline events have been flushed (even if 0 events were queued):
```json
{
  "op": "replay_complete",
  "latest_seq": 4821
}
```

#### 4. Client → Server: Acknowledge Delivery (`ack`)
```json
{
  "op": "ack",
  "seq": 4821
}
```
Server deletes queued offline events for this device with `seq <= 4821`.

#### 5. Server → Client: Error (`error`)
```json
{
  "op": "error",
  "code": "PAYLOAD_TOO_LARGE",
  "message": "event exceeds 64KB limit"
}
```

## 4. Inner Payloads (Decrypted JSON — Never Visible to VPS)

After decrypting `ciphertext` with `K_event` and `AAD = "v1|" + event_id + "|" + sender_device_id`, the plaintext is UTF-8 JSON with a `type` field.

### `notification.posted`
```json
{
  "type": "notification.posted",
  "notification_uid": "dev_01J...:1764060000123:a8f3c1",
  "sender_device_name": "Pixel 9",
  "posted_at": 1764060000123,
  "app": {
    "package": "com.whatsapp",
    "name": "WhatsApp",
    "icon_sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
    "icon_blob_id": "icon_e3b0c44298fc1c14"
  },
  "content": {
    "title": "Alice",
    "body": "Are we still on for dinner at 7?",
    "sub_text": "2 messages",
    "category": "msg",
    "group_key": "whatsapp:alice"
  },
  "attachments": [
    {
      "kind": "image",
      "blob_id": "img_01JABCDEF1234567890",
      "mime": "image/webp",
      "width": 800,
      "height": 600,
      "size_bytes": 84210,
      "sha256": "9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
    }
  ]
}
```

Field notes:
- `notification_uid`: Globally unique identifier for this notification instance (used for dismissal sync).
- `app.icon_blob_id`: Optional; present when the sender ensured the encrypted `64×64` WebP icon exists on the VPS. Receivers check their local cache by `icon_sha256` first and only fetch `icon_blob_id` on a cache miss.
- `attachments`: Optional array (usually 0 or 1 item for `BigPictureStyle` / `MessagingStyle` photo or contact avatar).

### `notification.dismissed`
```json
{
  "type": "notification.dismissed",
  "notification_uids": [
    "dev_01J...:1764060000123:a8f3c1"
  ],
  "dismissed_at": 1764060045000,
  "dismissed_by_device_name": "MacBook Pro"
}
```
- `notification_uids` is an array so dismissing a deduplicated/merged notification clears it on every originating phone in one event.

### Phase 6 (`v1.1`) Additive Extensions
- Outer WS `relay`/`event` adds optional `ephemeral: true` (online-only fan-out, `seq: 0`, no offline queue or ACK), targeted `target: "dev_<id>"`, and server `device_offline` frame.
- `notification.posted` adds optional `live` metadata (`replace_key`, `is_ongoing`, `progress`, `progress_max`, `indeterminate`).
- New ephemeral inner payloads: `media.state` and `media.command`, plus `art_<hash16>` album art blobs. See [LIVE_AND_MEDIA.md](./LIVE_AND_MEDIA.md).

## 5. HTTPS E2EE Blob API (Icons & Image Attachments)

All endpoints require `Authorization: Bearer <device_token>`.

| Method & Path | Purpose | Limits / Behavior |
| :--- | :--- | :--- |
| `HEAD /v1/blobs/{blob_id}` | Check if an encrypted blob (e.g. `icon_<hash_prefix>`) already exists on the VPS. | Returns `200 OK` if present (and refreshes TTL for icons) or `404 Not Found`. |
| `PUT /v1/blobs/{blob_id}` | Upload encrypted blob (`application/octet-stream`). | Max size **550 KB** (512 KB plaintext + AEAD overhead). Stored with **24h TTL**. Idempotent for same `blob_id`. |
| `GET /v1/blobs/{blob_id}` | Download encrypted blob. | Returns raw ciphertext bytes (`application/octet-stream`) or `404 Not Found` if expired. |

### `blob_id` Naming Rules
- Regex: `^[a-zA-Z0-9_-]{8,64}$`
- App icons: `icon_<first_16_hex_chars_of_sha256>` (deterministic so multiple phones share the same encrypted icon upload without duplicating storage).
- Media album art (Phase 6): `art_<first_16_hex_chars_of_sha256>` (deterministic `≤256×256` WebP, TTL refreshed on `HEAD` like icons).
- Image attachments: `img_<ULID>` (unique per attachment).

## 6. Cross-Language Test Vectors

Before implementing client/server crypto, `protocol/test_vectors.json` will provide fixed inputs and expected outputs for:
1. `K_master` → `K_event` and `K_blob` via HKDF-SHA256.
2. `XChaCha20-Poly1305` encrypt/decrypt with fixed 24-byte nonce and AAD for both an event and a blob.
3. Pairing URI parsing/encoding.

All three test suites (`go test`, `./gradlew test`, `cargo test`) MUST run and pass against `protocol/test_vectors.json`.
